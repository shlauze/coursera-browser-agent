# Coursera Browser Agent v2 — 0.2.87

Текущая реализация локального агента для Coursera. Исполнитель читает **My Learning → In Progress**, выбирает тесты, задания и лабораторные, сохраняет состояние и показывает ход работы в браузерной панели.

[Главная страница проекта](../README.md) · [Установка и обновление](SETUP_OTHER_USER.md) · [Сборка и запуск EXE](WINDOWS_EXE_RU.txt) · [Код](v2/) · [Тесты](tests/)

## Установка и первый запуск

Нужны Windows x64, Google Chrome, Python с командой `py` (окружение проекта — 3.14), интернет и собственный ключ Groq. Все команды ниже выполняются в этой папке, `browser-agent-v2/`.

```powershell
.\setup.cmd
.\.venv\Scripts\python.exe -X utf8 -m v2.cli configure-groq
.\run.cmd
```

`setup.cmd` создаёт `.venv` и устанавливает зависимости из `requirements.txt`. Программа подключается к установленному Chrome через CDP; отдельная установка браузера Playwright для запуска агента не требуется.

Откройте [http://127.0.0.1:8766/](http://127.0.0.1:8766/) и нажмите **«Запустить»**. При необходимости войдите в Coursera в отдельном Chrome. Если исполнитель уже остановился из-за отсутствия входа, запустите его снова после входа. Для предварительного входа без выполнения заданий используйте [инструкцию новой установки](SETUP_OTHER_USER.md#вход-без-выполнения-заданий).

Панель запускается без исполнителя. `serve --autostart` явно включает запуск сразу после старта панели. Установка не создаёт службу Windows или задачу автоматического запуска.

## Команды и порты

Префикс всех команд:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli
```

| Аргументы | Назначение |
| --- | --- |
| `--help` | Полный список команд |
| `serve` | Запустить только панель |
| `serve --autostart` | Запустить панель и исполнитель |
| `run` | Запустить исполнитель без новой панели |
| `scan` | Считать список My Learning, не открывая задание |
| `status` | Вывести сохранённое состояние JSON |
| `pause` | Запросить паузу на контрольной точке |
| `resume` | Продолжить после паузы |
| `stop` | Запросить штатную остановку |
| `skip COURSE_ID` | Исключить курс из очереди |
| `unskip COURSE_ID` | Вернуть исключённый курс |
| `configure-groq` | Ввести и сохранить основной ключ |
| `configure-groq --monitor-name NAME` | Зарегистрировать дополнительный ключ для пассивного учёта |
| `check-groq` | Отправить синтетический вопрос в Groq; расходует квоту |

ID курса доступен в `status`; в панели пропуск и возврат выполняются кнопками курса.

По умолчанию панель слушает `127.0.0.1:8766`, Chrome CDP — `127.0.0.1:9224`. Общий аргумент `--chrome-port` ставится **до** команды, а `--panel-port` — после `serve`:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli --chrome-port 9225 serve --panel-port 8767
```

Одна база и профиль допускают одного исполнителя; панель может работать одновременно с ним. Блокировка `data/runner.lock` предотвращает дублирующий запуск в той же установке. Для разных установок нужны отдельные папки и свободные CDP-порты: существующий CDP endpoint переиспользуется без проверки, какой установке принадлежит его профиль. Не открывайте панель или CDP в сеть.

## Управление и восстановление

Панель обновляется каждые восемь секунд. Она показывает состояние, очередь, текущую операцию, ожидающие действия, события, расход токенов и наблюдения лимитов Groq.

Пауза и остановка выполняются на контрольных точках. Текущая операция браузера может завершиться раньше, чем исполнитель обработает запрос. Для остановки из второго PowerShell:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli stop
.\.venv\Scripts\python.exe -X utf8 -m v2.cli status
```

Дождитесь `"control_state": "stopped"`. Для нового запуска используйте `run` или кнопку **«Запустить»**. `resume` работает только в состоянии паузы. После остановки закройте панель через Ctrl+C в её терминале. Chrome обычно остаётся открытым: отключение Playwright не закрывает пользовательское окно.

Перед действием, которое может отправить работу, исполнитель сохраняет намерение в SQLite. После прерывания он сначала сверяет результат с Coursera. Если отправка остаётся неопределённой, требуется проверка; сброс базы или повторный клик не являются восстановлением.

Некоторые задания откладываются, пока очередь продолжает работу. В панели сохраняется причина: например, нужен файл, подтверждение авторства, разбор изображения или поддерживаемое окружение лабораторной.

Неизвестные диалоги Coursera могут потребовать ручной проверки. Обработчик закрывает только распознанный опрос качества перевода Pendo через его кнопку закрытия, без рейтинга и ответа. Изменённая разметка, неоднозначная кнопка или дополнительные условия требуют проверки. Если окно остаётся открытым, курс может быть отложен, пока очередь продолжает работу.

## Какие задания обрабатываются

Текущий режим включает тесты, задания и лабораторные. Видео, чтения и другие учебные материалы не выполняются и не получают искусственных отметок завершения. Существование отдельного адаптера в коде не означает, что текущая очередь выберет этот тип материала.

| Вид работы | Условия |
| --- | --- |
| Квизы и формы заданий | Распознанная структура вопросов и ответов, проверка формы перед изменением, разбор доступной обратной связи |
| Graded Python labs | Поддерживаемый classic Jupyter, однозначно найденный ноутбук и ядро |
| Файловые задания | Заранее назначенный непустой локальный файл с совпадающими URL и SHA-256 |
| Peer assignments / review | Поддерживаемый маршрут, фактический текст работы и данные критериев; при отсутствии нужных данных — проверка пользователем |
| Неизвестные формы и окружения | Сохранение причины и отложенная обработка |

В ноутбуках редактируются разрешённые ячейки решения; защищённые преподавательские ячейки и тесты сохраняются. Исполнитель выполняет код, учитывает traceback и показывает выполнение ячеек. Успешный локальный тест, сохранение и Submit не заменяют удалённую оценку Coursera.

Общая оценка задания не доказывает правильность каждого ответа. Подтверждение успешного задания требует распознанного результата Coursera. Завершение курса проверяется отдельно: страница `/account/accomplishments/verify/` должна содержать совпадающий заголовок курса и текст о завершении. Прогресс 100% или зелёная отметка одного задания не заменяют такую проверку.

## Настройки отбора заданий

Настройки хранятся в собственной SQLite-базе. Новая установка не наследует настройки другого пользователя.

| Ключ метаданных | Поведение |
| --- | --- |
| `required_assessments_first` | По умолчанию `False`. При `True` явно обозначенные типом Practice задания исключаются, а graded получают приоритет |
| `user_skipped_item_kinds` | По умолчанию пустой список. Исключает точное видимое название типа, без учёта регистра, например `Programming Assignment` |
| `skip_file_upload_assignments` | По умолчанию `False`. При `True` исключает распознанные формы Upload File до загрузки и подтверждений |
| `user_skipped_file_assignments` | Записи конкретных форм, уже распознанных и исключённых пользователем; учитываются по ID курса и URL |
| `auto_confirm_coursera` | По умолчанию `False`; личное подтверждение остаётся действием пользователя |
| `allow_random_duplicate_options` | По умолчанию `False`; одинаковые тексты вариантов требуют проверки |

**Programming Assignment и Upload File не исключены по умолчанию.** Точная строка `Programming Assignment` не совпадает с `Practice Programming Assignment`. Настройки исключения сохраняются между запусками и не означают сдачу, отмену незавершённой отправки или получение сертификата.

Явная пометка `Optional:` в заголовке и отдельно сохранённые проверенные исключения также учитываются. Одно слово в произвольном названии не превращает неизвестное задание в необязательное.

Расширенные настройки меняйте только при остановленном исполнителе, сохраняя резервную копию базы. Для файлового задания адаптер ожидает `file_source:<базовый URL задания>` с полями `assignment_url`, `path` и `sha256`. Отсутствующий, пустой или изменившийся файл не отправляется. Файл выбирает и проверяет пользователь.

## Groq, ключи и ожидание

Groq — единственный провайдер; Ollama и автоматического переключения нет. Модель по умолчанию в коде — `openai/gpt-oss-120b`. Переменная окружения `GROQ_MODEL` позволяет явно задать модель для запуска.

`configure-groq` скрывает ввод и сохраняет ключ в `data/.groq-key.dpapi` через Windows DPAPI. Ключ связан с текущей учётной записью Windows; на другом компьютере или под другим пользователем настройте его заново. Сохранённый ключ имеет приоритет над `GROQ_API_KEY`.

`configure_groq.cmd` объединяет настройку и **реальный** `check-groq`. Если проверка связи не нужна, используйте прямую команду `configure-groq`, как в быстром старте. Проверка задаёт синтетический арифметический вопрос и ничего не отправляет в Coursera.

При HTTP 429 исполнитель сохраняет `Retry-After`, ждёт и повторяет запрос с тем же выбранным ключом. Пауза и остановка доступны во время ожидания. Перезапуск не сокращает сохранённый срок, а истечение срока не гарантирует восстановление всей квоты.

Дополнительные именованные ключи сохраняются зашифрованно для пассивного учёта. Регистрация не выбирает ключ и не отправляет запрос. Панель показывает последние наблюдения по ключу и модели; для неиспользованных ключей данные неизвестны. Квоты могут быть общими для организации. Автоматической ротации и запросов для проверки оставшейся квоты нет.

Автоматическое продолжение после ожидания работает, пока запущен исполнитель. После ручной остановки нужен новый запуск.

## Локальные данные

| Путь | Содержимое |
| --- | --- |
| `data/state.sqlite3` | Очередь, настройки, черновики, обратная связь и журнал действий |
| `data/*.dpapi` | Зашифрованные ключи |
| `profile/` | Отдельный профиль Chrome и авторизация |
| `logs/` | Журналы выполнения |
| `backups/` | Локальные резервные копии, если созданы |

Эти данные не включаются в Git. Они могут содержать личные сведения и учебные материалы; проверяйте содержимое перед передачей диагностик. Текст задания и необходимый контекст отправляются в Groq при обращении к модели.

Не переносите чужие базу, cookies или ключи. При обновлении своей установки сохраните собственные `data/` и `profile/`. [Порядок обновления](SETUP_OTHER_USER.md#обновление-своей-установки) включает штатную остановку и резервное копирование.

## Проверка кода

```powershell
.\run_tests.cmd
```

Команда запускает `unittest discover -s tests -v` из виртуального окружения. Проверки используют временные базы, моки и локальные фикстуры. Браузерным тестам нужен установленный Google Chrome. Фикстуры classic Jupyter используют дополнительные зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Эти зависимости нужны на машине разработки, а не на сервере Coursera. Скрипты `tests/live_navigation_check.py` и `tests/diagnose_discovery.py` — отдельные диагностические инструменты; стандартная команда `run_tests.cmd` не запускает их.

## Локальная сборка Windows EXE

```powershell
.\build_exe.cmd
```

Скрипт создаёт `.build-venv`, устанавливает закреплённые зависимости из `requirements-build.txt`, собирает `dist\CourseraAgent-0.2.87.exe` и запускает `--self-test`.

EXE содержит Python и Playwright. Google Chrome, учётные записи и ключ Groq нужны отдельно. Локальная сборка не создаёт GitHub Release; опубликованные бинарные файлы могут отставать от исходников. Подробности — в [WINDOWS_EXE_RU.txt](WINDOWS_EXE_RU.txt).
