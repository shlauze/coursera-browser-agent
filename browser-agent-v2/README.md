# Coursera Browser Agent v2 — 0.2.67

Локальный инструмент для Windows: отдельный профиль Chrome, панель управления,
SQLite с прогрессом и интеграция с Groq. Сертификат считается подтверждённым
только после проверки страницы Coursera с точным названием курса.

## Запуск EXE без установки Python

Версия 0.2.67 доступна в исходниках и локальной сборке EXE. Файл этого релиза
пока не опубликован. [Опубликованные сборки](https://github.com/shlauze/coursera-browser-agent/releases)
могут отставать от исходников. Для сборки 0.2.67 выполните `build_exe.cmd`
на Windows с Python; готовый EXE затем запускается без установленного Python.

Архив `Code → Download ZIP` содержит исходники, готового EXE в нём нет.

Положите EXE в доступную для записи папку. Для продолжения существующей работы
это должна быть прежняя папка с `data`, `profile` и `logs`.
Откройте PowerShell в этой папке и проверьте файл:

```powershell
Test-Path .\CourseraAgent-0.2.67.exe
.\CourseraAgent-0.2.67.exe --version
```

Ожидаются `True` и `0.2.67`. Если файл не найден, скачайте его или исправьте
текущую папку командой `cd "ПОЛНЫЙ ПУТЬ К ПАПКЕ С EXE"`.

### Первый запуск через панель

```powershell
.\CourseraAgent-0.2.67.exe
```

Введите свой ключ Groq в консоли, если он ещё не настроен. Ввод скрыт.
Панель откроется по адресу http://127.0.0.1:8766/. Нажмите кнопку запуска;
в отдельном Chrome войдите в Coursera вручную, если потребуется.
Консоль оставьте открытой. Без аргументов EXE открывает панель, исполнитель
самостоятельно не стартует.

### Прямой запуск исполнителя

После настройки ключа и входа в Coursera:

```powershell
.\CourseraAgent-0.2.67.exe --chrome-port 9224 run
```

Эта команда не открывает новую панель. Не запускайте одновременно второй
исполнитель через панель или из другого терминала.

### Другие команды

Выполняйте их из папки с EXE. Для управления работающим исполнителем откройте
второе окно PowerShell:

```powershell
# Настроить или заменить ключ (ввод скрыт)
.\CourseraAgent-0.2.67.exe configure-groq

# Просмотреть сохранённое состояние
.\CourseraAgent-0.2.67.exe status

# Пауза и продолжение работающего исполнителя
.\CourseraAgent-0.2.67.exe pause
.\CourseraAgent-0.2.67.exe resume

# Штатная остановка на безопасной точке
.\CourseraAgent-0.2.67.exe stop

# Диагностика комплекта без запросов к Coursera/Groq
.\CourseraAgent-0.2.67.exe --self-test
```

После `stop` дождитесь `control_state: stopped` в выводе `status`.
Для запуска остановленного исполнителя используйте `run`, а не `resume`.

### Панель с указанным портом

```powershell
.\CourseraAgent-0.2.67.exe --chrome-port 9224 serve --panel-port 8769
```

Откройте http://127.0.0.1:8769/ вручную. При явном `serve` браузер с панелью
автоматически не открывается. Не запускайте вторую панель на занятом порту;
для обновления закройте прежнюю после остановки её исполнителя.

## Запуск из исходников через Python

Установите Python и Google Chrome. Клонируйте репозиторий либо распакуйте
архив исходников и перейдите в подпапку `browser-agent-v2`:

```powershell
git clone https://github.com/shlauze/coursera-browser-agent.git
cd coursera-browser-agent\browser-agent-v2
.\setup.cmd
.\configure_groq.cmd
.\run.cmd
```

`run.cmd` запускает панель без автоматического запуска исполнителя.
Откройте http://127.0.0.1:8766/ вручную. Стандартный Chrome CDP-порт: 9224.

Прямой запуск из папки `browser-agent-v2`, если `.venv` уже настроена:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli --chrome-port 9224 run
```

Выберите EXE или Python — один исполнитель за раз.
Для самостоятельной сборки EXE: `build_exe.cmd` (сборщику требуется Python).

## Обновление без потери прогресса

1. Выполните `stop`, дождитесь `control_state: stopped` и закройте старую панель
   через Ctrl+C в её консоли.
2. Сделайте резервную копию каталогов `data`, `profile`, `logs`.
3. Положите новый EXE в ту же папку. Не удаляйте эти каталоги и не переносите
   один EXE в пустую папку, если хотите продолжить прежнюю работу.
4. Проверьте `--version`, затем запустите панель или `run`.

Ключ DPAPI привязан к пользователю Windows. На другом ПК настройте свой ключ.
EXE не подписан сертификатом издателя; SHA256 опубликованы в релизе.
Полная инструкция: [настройка для другого пользователя](SETUP_OTHER_USER.md).

  отмечается событием OLLAMA_RESPONSE и ещё не означает зачёт задания.
- После неудачного локального запроса уже истёкшее ожидание Groq не повторяется.

## Продолжение очереди в 0.2.65

Повторная команда `run` сообщает, что исполнитель уже работает, без сообщения
о падении основного процесса и без второго исполнителя. При ошибке модели
или неподдерживаемом задании программа сохраняет причину и продолжает другие
обязательные задания внутри курса. Неопределённые отправки сохраняются для сверки.
Панель показывает длительность текущего запроса Ollama; получение ответа ещё
не означает зачёт. Для файлов и внешнего peer-review по-прежнему нужны
пользовательские материалы и результаты проверки.

## Выбор Groq / Ollama / автоматически

В панели откройте **«Модель и автопереключение»** (`/providers`).
Выберите карточку режима и установленную модель Ollama, затем сохраните выбор.

- **Только Groq** — облачная генерация с ожиданием лимитов.
- **Только Ollama** — локальная генерация без запросов к Groq.
- **Автоматически** — Groq с переходом на Ollama при долгом ограничении или временной ошибке.

Во время работы выбор сохраняется как ожидающее изменение и применяется перед
следующим новым запросом к модели. Текущий запрос и ожидание Groq не прерываются.
Можно отменить ожидающее изменение. При остановленном исполнителе выбор сохраняется
сразу; сам исполнитель не запускается. Пауза, ответы и прогресс сохраняются.
Страница показывает применённый выбор и ожидающее изменение отдельно.

Ollama должна работать на том же компьютере по адресу `http://127.0.0.1:11434`.
Выберите установленную модель из списка. Программа не скачивает модели автоматически.
Список обновляется при перезагрузке страницы настроек. Выбор сохраняется в существующей базе.
После сохранения вернитесь в панель и запустите исполнителя.

Контекст Ollama выбирается отдельно: 8192, 16384 или 32768. Больший контекст требует
больше памяти. Программа консервативно оценивает размер запроса по UTF-8 и отклоняет
слишком большой запрос без обрезки кода, инструкции или feedback. В автоматическом
режиме такой запрос останется на Groq. При недоступной локальной модели показывается
событие `OLLAMA_UNAVAILABLE`.

Прогресс, черновики и подтверждённые ответы общие для обоих провайдеров. Ответ Ollama
проходит проверку JSON, вариантов ответа и ограничений исполнителя. Проверки преподавателя
и подтверждение результата Coursera сохраняются. Локальные токены не включаются в расход Groq.
Качество ответов зависит от модели: валидный JSON не гарантирует правильное решение.

Остановка проверяется и во время локальной генерации. Ответ, пришедший после остановки,
не применяется; соединение с Ollama закрывается для отмены генерации на сервере.
Используется [локальный API Ollama с JSON Schema](https://docs.ollama.com/capabilities/structured-outputs).

## Последние изменения

- **0.2.61:** выбор Groq/Ollama и автоматическое переключение при лимите или временной
  ошибке Groq; сохранение Retry-After, общей памяти ответов и проверок результатов.


- **0.2.60:** распознаётся короткое окно старта «You have 20 minutes to submit
  this attempt». Продолжение разрешено только после проверенного Start/Resume;
  существующее окно сначала закрывается для сверки результата предыдущей попытки.
  Неизвестные условия и повторная отправка без проверки результата блокируются.


- **0.2.59:** боковое меню курса, открытое как модальное окно Coursera,
  больше не останавливает чтение и раскрытие модулей. Неизвестные окна
  и подтверждения внутри меню по-прежнему требуют проверки пользователя.


- **0.2.58:** проверенное решение сохраняется локально до редактирования ячейки.
  При занятом ядре исполнитель ждёт до 60 секунд; после остановки использует
  черновик без нового запроса Groq, если исходный ноутбук и feedback не изменились.
  Неопределённые ошибки записи автоматически не повторяются.

- **0.2.57:** если ядро занято до отправки кода, исполнитель ждёт до 60 секунд.
  Явный отказ до запуска сохраняется как «не запускалось» и не блокирует
  следующую попытку. Неопределённые запросы выполнения автоматически не повторяются.

- **0.2.56:** ожидание генерации Groq, Retry-After и сетевых повторов больше
  не расходует часовой бюджет выполнения лабораторной. Проверки остановки,
  ограничения запросов и тайм-ауты выполнения ячеек сохранены.

- **0.2.55:** распознавание типа сохраняет отметку Practice у программных
  заданий, лабораторных и квизов. В режиме только обязательных заданий они
  исключаются из очереди без ложной отметки о выполнении.

- **0.2.54:** незагруженный график считается временным состоянием страницы.
  Исполнитель дожидается декодирования изображения в пределах обычного тайм-аута,
  затем сверяет описание; неизвестные и изменившиеся изображения остаются заблокированы.

- **0.2.53:** при сверке проверенных графиков Coursera учитывается обновление
  параметров доступа expiry/hmac на известном CDN. Путь файла, размеры
  и остальные параметры изображения по-прежнему должны совпадать.

- **0.2.52:** текстовая модель может использовать отдельно проверенное описание
  графика из локального хранилища. Совпасть должны вопрос, адрес и размеры
  изображения. Новые изображения, canvas/video и картинки в вариантах ответа
  по-прежнему требуют визуальной проверки. Описания не публикуются в репозиторий.
  Явная отметка Coursera «вопрос не отвечен» сохраняется как пустой ответ:
  оценка сверяется, варианты ответа в память не выдумываются.

- **0.2.51:** после `json_validate_failed` при подготовке лабораторной выполняется
  один повтор с уточнённым форматом JSON. Строгая схема и защита кода преподавателя
  сохраняются; повторная ошибка останавливает обработку. Отклонённый текст не используется.

- **0.2.50:** при сетевом тайм-ауте или HTTP 5xx допускаются до трёх попыток
  чтения состояния ядра и проверки сохранённого файла Jupyter. Повторяется
  только GET; запуск ячейки, сохранение и отправка задания не повторяются.

- **0.2.49:** объявленные в комментариях шаблона локальные переменные больше
  не связывают пустое решение с посторонними примерами обучения. В запрос
  включаются только блоки выбранной ячейки; настоящие зависимости сохранены.

- **0.2.48:** пустые блоки решения внутри циклов больше не заставляют добавлять

- **0.2.47:** обрезанный ответ Groq для лабораторной не применяется; при

  Увеличенный лимит сохраняется для того же контекста после перезапуска.
  Повторное обрезание останавливает обработку; Retry-After сохраняет приоритет.

- **0.2.46:** для ячеек с явными границами решения Groq возвращает только
  содержимое пронумерованных блоков. Исполнитель сам собирает ячейку,

- **0.2.45:** пустые блоки `YOUR CODE STARTS HERE` / `YOUR CODE ENDS HERE`

## Ограничения

Не все редакторы и лабораторные поддерживаются. Неопределённый результат,
неизвестное подтверждение или недостаток данных требуют ручной проверки.
Скрипт не гарантирует правильность ответа или получение сертификата.
Не подтверждайте авторство чужой или сгенерированной работы как собственной;
соблюдайте условия курса. Пропуск видео не создаёт ложных отметок завершения.

Лимиты Groq соблюдаются: перезапуск не восстанавливает квоту.
Незавершённые отправки не повторяются без сверки с Coursera.

## Локальные данные

`data/`, `profile/`, `logs/`, `backups/`, `.env` и `.venv/` исключены из Git.
Новый пользователь должен использовать собственные аккаунты и чистую базу.
Не включайте ключи, cookies, ответы, историю попыток или сертификаты в коммиты.

Код: `v2/`; тесты: `tests/`; команды CLI: `python -m v2.cli --help`.

## Потоковая Ollama в 0.2.66

Панель показывает число фрагментов, размер поступившего ответа и время последнего обновления. До первого фрагмента отображается ожидание обработки запроса, без утверждения, что ответ уже генерируется. Длительный активный поток больше не обрывается на 15-й минуте. Частичный, оборванный, превышающий бюджет или не соответствующий JSON Schema ответ не применяется. Стоп закрывает HTTP-соединение, в том числе до получения заголовков. Подтверждение зачёта по-прежнему требует отметки Coursera.

## Graded labs в 0.2.67

Поддерживаются graded Python labs в classic Jupyter. Исполнитель сохраняет копию
ноутбука, редактирует только выделенные ячейки решения, выполняет код и тесты,
использует traceback для исправлений и отдельно проверяет отметку Coursera.

- Совпадающие представления одного ноутбука и ядра переиспользуются. Разные ядра,
  исходники, пути или origins остаются неоднозначностью; чужие вкладки не закрываются.
- Синтаксическая ошибка ответа исправляется до записи в ноутбук: максимум три
  кандидата с передачей конкретной ошибки. Одинаковый ошибочный кандидат завершает
  попытки; история ошибок сохраняется при перезапуске. Смена модели или входных
  данных даёт новый бюджет. Защита преподавательских ячеек остаётся обязательной.
- После ошибки выполнения неизменённое решение повторно не запускается.
- Панель и журнал показывают начало, номер, состояние и завершение ячейки.
  Длительное обучение модели внутри ячейки видно отдельно от ожидания Groq/Ollama.
- Сохранение, выполнение и отправка не являются зачётом. Неопределённая отправка
  требует сверки; повторной отправки автоматически не происходит. Подтверждение
  личного авторства остаётся действием пользователя. Неподдерживаемое окружение
  сохраняется как блокировка конкретного задания.
