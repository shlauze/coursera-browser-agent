# Настройка для другого пользователя (0.2.32)

## 1. Отдельная установка

Нужны Windows, установленный Python 3.11+ с командой `py`, Google Chrome
и собственный аккаунт Groq. Код проверялся на Python 3.14.
Склонируйте репозиторий и перейдите в папку новой реализации:

```powershell
git clone https://github.com/shlauze/coursera-browser-agent.git
cd .\coursera-browser-agent\browser-agent-v2
```

Все следующие команды выполняются внутри `browser-agent-v2/`.
Не копируйте чужие `data/`, `profile/`, `logs/`, `backups/` и `.venv/`.
Для смены пользователя используйте новую папку и свободный CDP-порт:
подключение к занятому порту может открыть чужой профиль Chrome.

```powershell
.\setup.cmd
.\configure_groq.cmd
.\.venv\Scripts\python.exe -c "import v2; print(v2.__version__)"
```

Ожидаемая версия: `0.2.32`. Введите свой ключ в интерактивном приглашении.
Ключ сохраняется с Windows DPAPI и привязан к текущей учётной записи Windows.
Чужой зашифрованный ключ не переносите. Команда `check-groq` делает реальный
запрос и расходует квоту; для обычной установки она не требуется.

## 2. Обязательные задания и ручные подтверждения

До запуска исполнителя настройте чистую базу:

```powershell
.\.venv\Scripts\python.exe -c "from v2.store import Store; s=Store('data/state.sqlite3'); s.set_meta('required_assessments_first', True); s.set_meta('auto_confirm_coursera', False)"
```

Явно помеченные Practice задания будут исключены, graded задания получат
приоритет. Неизвестные типы нельзя автоматически считать необязательными.
Автоматическое подтверждение Coursera для нового пользователя выключено:
прочитайте условия самостоятельно. Привязки к курсу прежнего пользователя
в чистой базе нет.

## 3. Войти в Coursera без выполнения заданий

Можно отдельно открыть профиль браузера, войти вручную и закрыть Python-команду:

```powershell
.\.venv\Scripts\python.exe -c "from v2.browser import BrowserSession; from pathlib import Path; b=BrowserSession(Path('profile').resolve(), port=9224); b.connect(); input('Sign in to Coursera, then press Enter: '); b.close()"
```

`b.close()` отключает Playwright, оставляя Chrome открытым.
Используйте собственный аккаунт; не переносите cookies другого человека.
Если Chrome не найден, укажите его путь в текущем PowerShell:

```powershell
$env:COURSE_V2_CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
```

## 4. Панель и запуск

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli serve
```

Откройте http://127.0.0.1:8766/ . Панель сама исполнителя не запускает.
После проверки настроек нажмите «Запустить». Запускайте только одного
исполнителя на одну базу и профиль. Chrome CDP и панель должны оставаться
локальными, не открывайте их в Интернет.

Если порты заняты, используйте отдельные порты для всей новой установки:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli --chrome-port 9225 serve --panel-port 8767
```

В команде входа из шага 3 также замените `9224` на `9225`.

## 5. Обновление существующей установки того же пользователя

Сначала штатно остановите исполнитель:

```powershell
.\.venv\Scripts\python.exe -m v2.cli stop
.\.venv\Scripts\python.exe -m v2.cli status
```

Дождитесь `control_state: stopped`. Сделайте личную резервную копию базы
через SQLite backup (не публикуйте её), затем нажмите Ctrl+C в терминале
старой панели. Обновите исходники через Git и повторите `setup.cmd`.
Сохраните собственные `data/` и `profile/`: в них находятся прогресс,
кэш ответов и незавершённые отправки. Не сбрасывайте базу ради снятия паузы.

Запустите панель и проверьте именно запущенный сервер из другого PowerShell:

```powershell
(Invoke-RestMethod 'http://127.0.0.1:8766/api/status').version
```

Ожидается `0.2.32`. Если видна старая версия, порт обслуживает старый сервер.
Закройте его в исходном терминале через Ctrl+C либо используйте другой порт.
Не завершайте все процессы Python или Chrome подряд.

## 6. Ожидания и восстановление

Панель обновляется каждые 8 секунд; показывает причину ожидания Groq и срок
следующего запроса (в версии 0.2.32 время отображается как UTC+5).
При HTTP 429 дождитесь срока: перезапуск не увеличит доступную квоту.
Сохранённые ответы используются повторно при неизменном контексте; новый
разбор, варианты ответа или модель могут потребовать нового запроса.

После прерванной отправки сначала проверяется результат Coursera.
Если он неопределён, выполните ручную проверку; не удаляйте запись отправки.
Сертификат проверяется также в My Learning → Certificates. Зелёные отметки
отдельных экзаменов сами по себе не заменяют подтверждённый сертификат.
