# Новая установка и обновление — 0.2.91

[Главная страница](../README.md) · [Подробное руководство](README.md) · [Windows EXE](WINDOWS_EXE_RU.txt)

Инструкция относится к исходникам 0.2.91. Новый EXE этой публикацией не выпускается; номер бинарного файла в GitHub Releases проверяйте отдельно.

## Новая установка

Нужны Windows x64, установленный Google Chrome, Python с командой `py` (окружение проекта — 3.14), интернет и собственные аккаунты Coursera и Groq.

Склонируйте репозиторий либо распакуйте **Code → Download ZIP** в отдельную папку. Для клонирования нужен Git:

```powershell
git clone https://github.com/shlauze/coursera-browser-agent.git
cd .\coursera-browser-agent\browser-agent-v2
.\setup.cmd
.\.venv\Scripts\python.exe -c "import v2; print(v2.__version__)"
.\.venv\Scripts\python.exe -X utf8 -m v2.cli configure-groq
```

Ожидаемая версия исходников — `0.2.91`. Все дальнейшие команды выполняются из `browser-agent-v2/`.

Введите свой ключ в скрытом приглашении. Он будет сохранён через Windows DPAPI для текущего пользователя. Команда `configure-groq` не делает тестового запроса. Отдельная команда `check-groq` расходует квоту Groq; обёртка `configure_groq.cmd` запускает её автоматически после настройки.

Для нового пользователя нужна чистая установка. Не копируйте чужие `data/`, `profile/`, `logs/`, `backups/` или `.venv/`. Автоматическое подтверждение авторства в новой базе выключено. Исключения Programming Assignment и Upload File также по умолчанию выключены.

## Вход без выполнения заданий

До запуска исполнителя можно открыть отдельный профиль Chrome и войти вручную:

```powershell
.\.venv\Scripts\python.exe -c "from v2.browser import BrowserSession; from pathlib import Path; b=BrowserSession(Path('profile').resolve(), port=9224); b.connect(); input('Sign in to Coursera, then press Enter: '); b.close()"
```

Дождитесь страницы My Learning, войдите в Coursera и нажмите Enter в терминале. Команда отключит Playwright и оставит Chrome открытым. Задания этим способом не выполняются.

Если Chrome не найден, укажите путь к своей установке в текущем PowerShell:

```powershell
$env:COURSE_V2_CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
```

## Панель и очередь

```powershell
.\run.cmd
```

Откройте [http://127.0.0.1:8766/](http://127.0.0.1:8766/). Панель сама исполнителя не запускает. Нажмите **«Запустить»**, чтобы начать обработку очереди.

Для чтения списка курсов без открытия задания, пока исполнитель остановлен:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli scan
```

Запускайте одного исполнителя на одну базу и профиль. Другой установке нужны отдельная папка и свободные порты:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli --chrome-port 9225 serve --panel-port 8767
```

В команде предварительного входа также замените `port=9224` на `port=9225`. Не подключайтесь к CDP-порту чужой установки: существующий Chrome переиспользуется. Панель и CDP должны оставаться доступны только локально.

## Остановка, пауза и ожидание

Кнопки панели и CLI используют одну сохранённую базу. Для остановки из второго PowerShell:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m v2.cli stop
.\.venv\Scripts\python.exe -X utf8 -m v2.cli status
```

Дождитесь `"control_state": "stopped"`. Для нового запуска используйте кнопку панели или `run`; `resume` продолжает только паузу.

При ограничении Groq исполнитель ждёт сохранённый `Retry-After`. Перезапуск не восстанавливает квоту. При неизвестном результате отправки сначала проверяется Coursera; не удаляйте запись отправки и не сбрасывайте базу. Необходимые личные подтверждения выполняйте самостоятельно в Coursera, затем продолжайте работу через панель.

## Обновление своей установки

1. Выполните `stop`, дождитесь состояния `stopped` и закройте старую панель через Ctrl+C в её терминале.
2. Сделайте личную резервную копию базы через SQLite backup. В PowerShell из папки программы:

   ```powershell
   .\.venv\Scripts\python.exe -c "from pathlib import Path; import sqlite3; from datetime import datetime; d=Path('backups'); d.mkdir(exist_ok=True); src=sqlite3.connect('data/state.sqlite3'); dst=sqlite3.connect(d / ('state-' + datetime.now().strftime('%Y%m%d-%H%M%S-%f') + '.sqlite3')); src.backup(dst); dst.close(); src.close()"
   ```

3. Сохраните собственные `data/` и `profile/`. Для резервной копии профиля сначала закройте его окно Chrome.
4. Обновите исходники через Git или замените только файлы программы из архива. Не перезаписывайте локальные данные и не переносите `.venv` между компьютерами.
5. Повторите `setup.cmd` и запустите `run.cmd`.

Проверьте версию именно запущенной панели из другого PowerShell:

```powershell
(Invoke-RestMethod 'http://127.0.0.1:8766/api/status').version
```

Ожидается `0.2.91`. Если ответ имеет старую версию, этот порт обслуживает старая панель. Закройте её в исходном терминале либо используйте другой порт. Не завершайте все процессы Python или Chrome подряд.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Chrome не найден | Установка Chrome и `COURSE_V2_CHROME_PATH` |
| Панель не открывается | Открыт ли терминал, правильный ли порт, нет ли старой панели |
| Coursera требует вход | Вход в отдельном профиле Chrome; после входа повторный запуск |
| Исполнитель на паузе | Сообщение панели и требуемое действие пользователя |
| Groq HTTP 429 | Сохранённый срок ожидания; оставьте исполнитель работающим для автоматического продолжения |
| Нужен файл или неизвестна оценка | Причина проверки в панели и фактическое состояние задания на Coursera |

Для проверки кода используйте `.\run_tests.cmd`; требования к тестовым фикстурам указаны в [руководстве](README.md#проверка-кода). Перед публичным issue удалите из диагностики ключи, cookies, личные сведения, ответы и ссылки на личные сертификаты.
