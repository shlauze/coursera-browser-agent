# Coursera Browser Agent

Локальный помощник для прохождения доступных вам курсов Coursera на Windows. Он работает через отдельный профиль Chrome, сохраняет прогресс между запусками и показывает состояние очереди в браузерном мониторе. Для ответов на поддерживаемые задания используется Groq API.

> **Версия:** `4.0-groq.54` · **Платформа:** Windows x64 · **Интерфейс Coursera:** английский

Репозиторий: [shlauze/coursera-browser-agent](https://github.com/shlauze/coursera-browser-agent). Для скачивания нужен доступ к нему в GitHub.

## Возможности

- Проверяет зелёные отметки и состав материалов в боковой панели курса, затем продолжает с незавершённого материала.
- Перед началом нового курса просматривает **все страницы My Learning → In Progress**. Сначала выбирает уже начатые курсы, затем курсы с `Get started`, и только после них новые ссылки из `courses.txt`.
- После последнего материала проверяет страницу сертификата **именно текущего курса**. Без подтверждённого сертификата не переключается на следующий курс.
- Сохраняет контрольные точки и историю попыток. После перезапуска заново сверяет состояние с Coursera, включая исход ранее отправленного теста.
- Повторяет только безопасное чтение страницы при временной ошибке Chrome или загрузки Coursera. Запоминает удачные восстановления и увеличивает для такого чтения ограниченный запас попыток на следующих запусках.
- Показывает очередь, текущий материал, события, причину остановки и доступные лимиты Groq на локальной панели. Из неё можно управлять запуском и выбирать курсы для пропуска.

Автоматическое выполнение зависит от разметки Coursera, доступности курсов и поддерживаемых типов заданий. Оно **не гарантирует** правильные ответы, проходной балл или сертификат.

## Что потребуется

| Компонент | Для чего нужен |
|---|---|
| Windows x64 | Поддерживаемая среда запуска и хранение ключа через Windows DPAPI |
| Python 3.14 | Локальный исполнитель; мастер установки может установить его через WinGet |
| Google Chrome | Отдельный профиль для Coursera; мастер установки может установить браузер |
| Учётная запись Coursera | Входите вручную в открывшемся окне; нужные курсы должны быть доступны вашему аккаунту |
| Ключ [GroqCloud](https://console.groq.com/keys) | Запросы модели для поддерживаемых заданий |
| Интернет | Coursera, Groq и первичная установка зависимостей |

Node.js нужен **только для полного набора тестов**, не для обычного запуска. Ollama и локальная видеокарта для модели не требуются.

## Установка

1. Откройте [репозиторий](https://github.com/shlauze/coursera-browser-agent) под учётной записью с доступом. Скачайте ZIP через **Code → Download ZIP** либо клонируйте проект:

   ```powershell
   git clone https://github.com/shlauze/coursera-browser-agent.git
   cd coursera-browser-agent
   ```

   Распакуйте ZIP полностью в отдельную папку с правом записи, если выбрали загрузку архива. Не запускайте `.cmd` из окна предпросмотра ZIP.
2. Запустите [setup_new_pc.cmd](setup_new_pc.cmd). Он проверит Python 3.14 и Chrome, при необходимости установит их через WinGet, создаст `.venv`, установит версии библиотек из [requirements.txt](requirements.txt) и проверит список курсов.
3. По запросу мастера вставьте **свой** ключ Groq. Ввод скрыт. Затем укажите отображаемое имя в Coursera точно как на сайте. Мастер сохранит настройки и проверит короткий запрос к API.
4. При необходимости измените [courses.txt](courses.txt): одна ссылка на курс в строке. Пример:

   ```text
   https://www.coursera.org/learn/example-course
   https://www.coursera.org/learn/another-course
   ```

   Допускаются ссылки вида `https://www.coursera.org/learn/<slug>`; пустые строки и строки с `#` игнорируются. Ссылки на специализации, уроки и отдельные задания не подходят. В списке должно быть от 1 до 500 уникальных курсов.

Если WinGet отсутствует, установите [Python 3.14](https://www.python.org/downloads/windows/) и [Chrome](https://www.google.com/chrome/) вручную, затем повторите `setup_new_pc.cmd`. Мастер устанавливает зависимости из интернета; необязательная локальная папка `wheelhouse`, если она есть, используется сначала.

Ключ или имя можно изменить позднее через [configure_groq.cmd](configure_groq.cmd). Файл `.groq-key.dpapi` привязан к текущему пользователю Windows: на новом компьютере настройку ключа нужно выполнить заново.

## Первый запуск

1. Дважды щёлкните [run_course.cmd](run_course.cmd) либо запустите его из PowerShell в папке проекта:

   ```powershell
   .\run_course.cmd
   ```

2. В открывшемся **отдельном** окне Chrome войдите в Coursera. Можно оставить открытыми несколько вкладок курсов: исполнитель выберет вкладку **My Learning**, если она есть, или одну из вкладок Coursera и сам откроет **In Progress**. Авторизацию, 2FA и CAPTCHA выполняйте сами.
3. Вернитесь в окно скрипта и нажмите **Enter**. Монитор откроется по адресу [http://127.0.0.1:8765/](http://127.0.0.1:8765/).

Для запуска без ожидания Enter используйте `.\run_course.cmd --yes` после того, как вход в Coursera уже выполнен. Команда `run_queue.cmd` запускает очередь без сторожевого перезапуска; для обычной работы используйте `run_course.cmd`.

Скрипт не требует вводить вопросы в терминал: он читает поддерживаемые задания со страницы. Закрытие вкладки монитора не останавливает очередь.

## Как выбираются курсы

До приглашения нажать Enter скрипт открывает **My Learning → In Progress** по адресу `https://www.coursera.org/my-learning?myLearningTab=IN_PROGRESS`. При повторном запуске он показывает уже открытую страницу или создаёт отдельную вкладку, сохраняя вкладку незавершённой отправки задания для проверки.

При старте скрипт проверяет настройки и сохранённые попытки. Несколько результатов тестов он сверяет по очереди; записи удалённых из очереди курсов сохраняет, но они не блокируют текущий запуск. Для старой отправки без сохранённого номера попытки достаточно текущего проходного результата **вместе с зелёной отметкой того же задания**. Неудачный результат без точного номера попытки остаётся неопределённым и не вызывает повторного Submit. При неудаче скрипт читает `View feedback` или `Review feedback`. Если доказать результат нельзя, попытка остаётся сохранённой, а очередь останавливается с конкретной причиной. После проверки скрипт возвращается на **My Learning → In Progress** и полностью читает все страницы, пока не выяснит состояние списка. При переходе между страницами он ждёт обновления самих карточек. Курсы программы без доступной кнопки запуска откладываются до завершения предыдущих курсов; если других заданий нет, очередь сообщает об этом. Ошибка или неоднозначность списка также останавливает очередь и сохраняет причину. Карточки курсов на этом этапе не открываются.

После полного обхода скрипт открывает выбранную карточку курса. При запуске он не открывает сохранённые страницы сертификатов: ранее подтверждённые сертификаты остаются в локальном состоянии. Порядок выбора:

1. Доступные карточки с кнопкой `Resume` на любой странице списка.
2. Карточки с кнопкой `Continue learning`, если Coursera показывает этот вариант.
3. Доступные карточки с кнопкой `Get started`.
4. Новые курсы из `courses.txt` в указанном порядке, если в **In Progress** нет доступных карточек.

После каждого нового подтверждённого сертификата проверка **In Progress** начинается заново. Если найден незавершённый курс с неизвестным состоянием или кнопкой, очередь остановится и покажет причину вместо того, чтобы пропустить курс. Курсы, найденные в My Learning, добавляются в локальный список. Даже удалённый из `courses.txt` ранее начатый курс может появиться вновь, если Coursera всё ещё показывает его незавершённым. Если список **In Progress** пуст, скрипт берёт только ещё не начатые курсы из `courses.txt`; старые локальные контрольные точки и сохранённые сертификаты не запускают обход страниц при старте. Опция `--manual-queue` отключает автоматический поиск My Learning и оставляет только настроенные ссылки.

Внутри курса скрипт сверяет состав модулей и зелёные отметки в Course outline, начинает с первого неподтверждённого материала и повторно проверяет зелёную отметку после каждого действия. При временном сбое чтения он повторно подключается к Chrome или открывает тот же материал и проверяет его статус. Если действие завершилось по таймауту, скрипт сначала проверяет зелёную отметку; отправка теста при этом не повторяется. После последнего материала скрипт открывает `View certificate page` или ищет сертификат этого курса во вкладке **Completed**. Если выдача сертификата задерживается, поиск повторяется ограниченное число раз. Одних зелёных галочек или поздравления недостаточно для перехода дальше.

## Панель управления

Панель открывается вместе с [run_course.cmd](run_course.cmd) по адресу [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Её можно запустить отдельно через [run_monitor.cmd](run_monitor.cmd), а затем запускать очередь кнопкой на странице. Панель и исполнитель — отдельные процессы: закрытие вкладки панели не останавливает выполняющийся курс, а закрытие окна `run_monitor.cmd` выключает только панель.

На странице видны текущий курс и материал, прогресс, события, лимиты Groq и причина остановки. Состояние обновляется автоматически; если исполнитель давно не сообщал о прогрессе, панель показывает предупреждение. Доступны основные действия:

| Действие | Что происходит |
|---|---|
| **Запустить / Продолжить** | Запускает исполнитель, если он ещё не работает. Повторный запуск сверяет сохранённую контрольную точку с Coursera. Два экземпляра очереди одновременно не запускаются. |
| **Приостановить** | На безопасной границе приостанавливает работу без потери прогресса. Исполнитель остаётся запущенным и ждёт команды **Продолжить**. |
| **Остановить** | Завершает текущий запуск с сохранением прогресса. Позже можно снова запустить очередь. |
| **Пропустить курс** | Откладывает выбранный курс и даёт очереди перейти к другому. Пропуск не означает прохождение курса и не создаёт сертификат. |
| **Вернуть курс** | Снимает пропуск, после чего курс снова может быть выбран из очереди. |
| **Добавить / убрать курс** | Меняет `courses.txt`. История уже начатого курса сохраняется. Удаление из списка и временный пропуск — разные действия. |

Нажимайте **Пропустить курс** для временного исключения: он остаётся в списке, а его контрольные точки сохраняются. **Убрать курс** удаляет ссылку из `courses.txt`; уже начатый курс может снова появиться, если Coursera всё ещё показывает его в **In Progress**. Прямая ссылка в карточке курса открывает его на Coursera. В списке должен оставаться хотя бы один курс.

Команды управления применяются на ближайшей безопасной границе между действиями. Если в момент нажатия открыта отправка теста или лабораторной, дождитесь проверки результата на Coursera: панель не считает незавершённую отправку успешной и не повторяет её вслепую. Открытое окно Chrome и сохранённые попытки остаются доступны для последующего запуска.

Если порт `8765` занят, используйте уже открытый монитор либо запустите другой порт:

```powershell
.\.venv\Scripts\python.exe -X utf8 .\progress_monitor.py --port 8766
```

Монитор слушает только `127.0.0.1` на этом компьютере. Не публикуйте его через прокси или туннель: данные прогресса могут содержать названия курсов и тексты заданий.

## Остановка и продолжение

- **Пауза:** используйте кнопку **Приостановить** на панели; исполнитель сохранит состояние на безопасной границе и будет ждать. Для продолжения нажмите **Продолжить**. `Ctrl+C` в окне скрипта по-прежнему прерывает запуск с сохранением состояния; затем можно снова открыть `run_course.cmd`.
- **Ошибка или неизвестный тип материала:** временные ошибки чтения скрипт обрабатывает сам. Если попытки исчерпаны или состояние задания неясно, прочитайте `COURSE_ATTENTION` в терминале и причину в мониторе. Локальный файл `incident.json` в папке последнего запуска содержит код этапа и тип ошибки без текста задания и ключей. После исправления причины снова запустите скрипт. До подтверждения сертификата он останется на текущем курсе.
- **Неожиданный выход Python:** `run_course.cmd` перезапускает исполнитель до трёх раз, пока сохранённая очередь имеет статус `running`. Сведения об этих перезапусках находятся в `logs/runner_supervisor.log`.
- **Временный сбой чтения после внутренних повторов:** `run_course.cmd` ещё до трёх раз перезапускает тот же курс с задержкой 30, 60 и 90 секунд. После нового подтверждённого материала, модуля или сертификата счётчик сбоев обнуляется. На каждом запуске исход сохранённых отправок проверяется заново. Неопределённый Submit, неподтверждённый сертификат и задание без обработчика не запускают такой цикл.
- **Лимит Groq или задержка повторной попытки Coursera:** исполнитель сохраняет контрольную точку и продолжает, когда это возможно. Время ожидания и причина остановки видны в мониторе.

Для обычного продолжения **не удаляйте `state/`**: там находятся контрольные точки и история попыток. Повторный запуск сверяет состояние с сайтом и не должен повторно отправлять попытку, чей результат ещё не определён.

Дополнительные параметры запуска:

```powershell
# Только проверить формат courses.txt, не открывая Chrome и не вызывая Groq
.\.venv\Scripts\python.exe -X utf8 .\course_queue.py --validate

# Ограничить тест тремя попытками в общей истории и выделить до 240 минут на курс
.\.venv\Scripts\python.exe -X utf8 .\course_queue.py --monitor --quiz-attempts 3 --minutes 240

# Использовать только courses.txt, не искать курсы в My Learning
.\.venv\Scripts\python.exe -X utf8 .\course_queue.py --monitor --manual-queue
```

По умолчанию `--quiz-attempts 0` означает повторы до проходного результата Coursera с учётом ограничений самой платформы. Лимит `--minutes` по умолчанию составляет 180 минут **без подтверждённого прогресса**: после каждой зелёной отметки отсчёт начинается заново. Ожидание доступности новой попытки учитывается отдельно.

## Поддерживаемые задания и ограничения

Поддерживаются обычные чтения и видео, некоторые тесты с выбором вариантов или числовым полем, `Lab` с кнопками `Launch lab` / `Mark as completed`, `Dialogue`, `Role Play`, а также некоторые факультативные текстовые `Practice Assignment`. После неудачной попытки теста скрипт читает подробный `Review feedback`, прежде чем пробовать ещё раз. Для `Dialogue` он использует подтверждение окончания и проверяет зелёную отметку. В `Role Play` он отвечает по показанным задачам, проверяет счётчик `Tasks` и итоговую обратную связь по каждому пункту. Если модель выдумывает результаты проверки, ответ не отправляется; для известного сценария об угрозе от сотрудника есть ответ с планом расследования без выдуманных данных. Зелёная отметка при `0/5` сама по себе не подтверждает выполнение: при доступной кнопке `Practice again` скрипт начинает новую сессию. Если задания или результат неоднозначны, работа останавливается с сохранением состояния.

**Programming Assignment** — отдельный оцениваемый тип, его нельзя завершить кнопкой `Mark as completed`. При неудачной прошлой попытке скрипт открывает `My submissions`, раскрывает `Show grader output`, читает `View grader feedback` и сохраняет подробный отчёт по проверкам. Затем он возвращается к заданию, открывает `Launch lab` или `Resume lab`, ждёт конечный адрес новой вкладки и классический Jupyter, проверяет ячейки, результаты открытых тестов и серверную копию блокнота. Промежуточный адрес `about:blank` или `/lab` без пути ноутбука не считается чужим заданием; содержимое фрейма читается только после подтверждения точного адреса нужной лаборатории. Отчёт сохраняется в игнорируемом Git каталоге `state/programming_diagnostics/`. Feedback старой отправки и состояние текущего блокнота в нём разделены: прежний низкий балл не описывает исправленные после отправки ячейки. Выводы открытых тестов могут быть устаревшими: без нового запуска и оценки Coursera они не подтверждают проходной балл.

В терминале появляется `PROGRAMMING_REVIEW` с причиной и нужным действием. После диагностики скрипт ещё раз проверяет зелёную отметку именно этого задания. Если Coursera уже подтвердила прохождение, он продолжит курс. Иначе лаборатория останется открытой для проверки; оценка `Failed` не считается завершением. Скрипт не переходит к следующему курсу без подтверждённого сертификата текущего. Если формат лаборатории неизвестен, он сообщает причину остановки без повторной отправки.

Скрипт обучается на успешных способах восстановления чтения страницы, но не переписывает исполняемый Python во время работы: непроверенный патч может повредить сохранённые попытки или профиль браузера. При новой разметке Coursera он сохраняет локальную диагностику для разработки отдельного исправления с тестами. Диагностика не отправляет оцениваемую работу. Coursera может показывать **Honor Code**: подтверждение, что работа выполнена вами самостоятельно, и предупреждение об использовании ИИ. Скрипт не ставит такую галочку за владельца аккаунта. Проверьте содержимое ноутбука и правила курса перед любой отправкой.

При `PROGRAMMING_REVIEW` откройте оставленную вкладку лаборатории и прочитайте отчёт, особенно `previous_feedback`, `unfinished_solution_cells` и `tests`. Перед отправкой лично проверьте блокнот и заново запустите его тесты: ранее сохранённые успешные выводы не доказывают, что текущий код выполнялся после изменений. После личной отправки и новой оценки Coursera снова запустите `run_course.cmd`: очередь сверит зелёную отметку, затем сертификат и только потом перейдёт к следующему курсу. Одинаковые сохранённые вкладки лаборатории можно оставить открытыми. Если одна из них содержит несохранённые изменения или недоступна, сохраните работу и закройте лишнюю вкладку: скрипт не выбирает случайную копию.

Остальные случаи, требующие участия человека или отдельного обработчика: peer review, эссе, загрузка файлов, неизвестные поля и виды лабораторных, задания с изображениями, многостраничные тесты, вход/2FA/CAPTCHA, оплата и новые интерфейсы Coursera.

## Проверка проекта

Проверка списка курсов без сети описана выше. Полный локальный набор регрессионных тестов:

```powershell
.\run_tests.cmd
```

Для него нужен Node.js в `PATH` и установленное окружение `.venv`. Тесты используют локальные макеты браузера и модели; они не входят в Coursera и не отправляют задания. Дополнительные сведения — в [tests/README.txt](tests/README.txt).

## Локальные данные и безопасность

| Путь | Содержимое |
|---|---|
| `courses.txt` | Настраиваемый список ссылок |
| `settings.json` | Локальное отображаемое имя Coursera |
| `.groq-key.dpapi` | Ключ Groq, зашифрованный для текущего пользователя Windows |
| `coursera-chrome-profile/` | Сессия отдельного профиля Chrome |
| `state/` | Очередь, контрольные точки и история попыток |
| `logs/` | Журналы запуска, события и диагностические данные |

`settings.json`, ключ, профиль Chrome, `state/`, `logs/` и `.venv/` являются **локальными данными**. Они не нужны другим пользователям для установки и не должны попадать в GitHub-репозиторий независимо от его настроек доступа. Перед отправкой изменений проверяйте список файлов `git status` и правила `.gitignore`: журналы и снимки страниц могут содержать ваши ответы и данные аккаунта.

Проект не запрашивает пароль Coursera в терминале. Вход выполняется в Chrome. Тексты поддерживаемых вопросов, варианты, обратная связь и реплики `Role Play` могут передаваться в Groq API для генерации ответов. Пользуйтесь проектом только с собственным аккаунтом и в рамках правил ваших курсов.
